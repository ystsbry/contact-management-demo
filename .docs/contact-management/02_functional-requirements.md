# 機能要件（MVP）

## 1. 受付 API（HP から呼ばれる）

- 氏名、メールアドレス、電話番号（任意）、問い合わせ種別、本文を受け取り保存する。
- 入力バリデーションを行い、HP 側が項目ごとにエラー表示できる形式で返す。
- Bot 対策トークン（Cloudflare Turnstile）を検証する。
- IP 単位のレート制限を行う（WAF）。
- CORS で HP のオリジンのみ許可する。
- 受付番号を発行し、レスポンスで HP に返す。HP はお客様に受付番号を表示する。
- 同じメールアドレスと本文の送信が 5 分以内に重複した場合は、既存の受付番号を返す（二重登録しない）。
- 問い合わせ種別の一覧を返す API を提供する（HP のセレクトボックス用）。

## 2. メール送受信

送信:

- 受付時にお客様へ自動返信メールを送る。件名に受付番号を含め、返信先を受信用アドレスにする。
- スタッフは管理画面からお客様へ返信メールを送れる。送った内容は履歴に残る。
- 返信メールは、お客様のメーラーで同じスレッドに並ぶようにヘッダを付与する。

受信:

- お客様からの返信メールを SES で受信し、受付番号をもとに該当の問い合わせへ紐付ける。
- 紐付け先が見つからないメールは、メール起点の新規問い合わせとして登録する。
- 自動応答（不在通知など）、ウイルス検知、スパム判定のメールは取り込まない。
- 同じメールを二重に取り込まない。
- お客様からの返信を受信したら、ステータスを戻し、担当者へ通知する。
- 受信メールの添付ファイルは MVP では画面に出さない。原本を S3 に保管し、添付があったことだけ記録して画面に表示する。

## 3. 管理画面

- ログイン後のトップに、未対応件数、要返信件数、自分の担当件数、直近の問い合わせを表示する。
- 一覧: ステータス、種別、担当者、要返信で絞り込み、受付日時の新しい順に表示、ページング。
- 検索: 氏名、メールアドレス、受付番号、本文のキーワード検索。
- 詳細: お客様情報、種別、ステータス、担当者、メッセージと内部メモとイベントを時系列に並べたタイムライン。
- 詳細からの操作: ステータス変更、担当者アサイン、メール返信、内部メモ追加。
- 同じメールアドレスの過去の問い合わせを一覧表示する。
- 「要返信」が一覧と詳細で分かる。

## 4. 認証・権限・設定

- メールアドレスとパスワードでログインする（Cognito）。
- 初回ログイン時に仮パスワードから本パスワードへ変更する。
- パスワードを忘れた場合、メールで届く確認コードで再設定できる。
- ロールは 管理者 / 担当者 の 2 種類。
  - 管理者: すべての操作、ユーザー管理、各種設定。
  - 担当者: 問い合わせの閲覧と対応操作。
- ユーザー管理: 追加（招待メール送信）、ロール変更、無効化、パスワードリセット。
- 自分のパスワード変更。
- 問い合わせ種別マスタ: 追加、名称変更、表示順、無効化。
- メール設定: 送信元の表示名、自動返信の件名と本文、スタッフ通知先アドレス、署名。

## 5. 通知（スタッフ向けメール）

| イベント | 通知先 |
|---|---|
| 新規問い合わせ（フォーム / メール起点） | 設定した通知先アドレス |
| 担当者アサイン | 担当者本人 |
| お客様からの返信受信 | 担当者本人。未割当なら通知先アドレス |

通知メールには受付番号、氏名、種別、本文冒頭、管理画面の詳細 URL を含める。

## 6. ステータス

| ステータス | 意味 |
|---|---|
| 未対応 | 誰も着手していない |
| 対応中 | 担当者が付いている、または対応を進めている |
| 返信済み | スタッフが返信し、お客様の反応待ち |
| 完了 | 対応が終わった |

自動遷移:

- 担当者をアサインすると 未対応 → 対応中。
- スタッフが返信を送ると → 返信済み。
- お客様の返信を受信すると、返信済み / 完了 → 対応中（担当者あり）または 未対応（担当者なし）。

手動変更はどのステータスへも可能。

## 7. 非機能要件

- HTTPS のみ。
- 個人情報（氏名、メール、電話、本文）はログインユーザーのみ閲覧できる。アプリケーションログに本文を出力しない。
- 性能要件は特になし（月数十件）。
- 対応ブラウザは最新の Chrome / Edge / Safari。
- 受信処理は冪等にし、SES や Lambda の再試行で重複登録しない。
- インフラはコードで管理し、再構築できる。
- バックアップは DynamoDB のポイントインタイムリカバリを有効にする。

## 8. HP 側への依頼事項

HP はこのリポジトリの範囲外だが、以下の実装が必要になる。

- Cloudflare Turnstile のウィジェットを埋め込み、取得したトークンを受付 API に渡す。
- 受付 API を呼び出し、成功時は受付番号を表示する。
- バリデーションエラー時は、API が返す項目別メッセージを表示する。
- 送信ボタンの連打を防ぐ（送信中は無効化）。
- 問い合わせ種別は種別 API から取得するか、管理画面で登録した ID を固定で埋め込む。
