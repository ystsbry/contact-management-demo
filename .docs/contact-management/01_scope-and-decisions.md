# 前提・スコープ・決定事項

## 前提

- お客様は別に存在するホームページ（以下 HP）のフォームから問い合わせる。HP 自体はこのリポジトリの範囲外。
- このリポジトリでは、HP から呼ばれる **受付 API**、社内スタッフが使う **管理画面**、**メール送受信基盤** を実装する。
- 受付サイトは 1 つ。マルチテナントは考慮しない。
- お客様とのやり取りは **メールで完結** させる。お客様向けの照会ページやマイページは作らない。
- お客様からの返信メールは **システムが受信し、該当の問い合わせに自動で紐付ける**。
- スタッフへの通知は **メールのみ**。Slack 等の連携は行わない。
- 規模は **月数十件、スタッフ数人**。自動割当、レポート、SLA 管理は不要。
- フロントエンドは TypeScript / React、バックエンドは Go、インフラは AWS の Lambda と CloudFront を軸にする。

## 用語

| 用語 | 意味 |
|---|---|
| 問い合わせ（Inquiry） | お客様からの 1 件の相談。受付番号で識別する |
| 受付番号 | `INQ-000123` 形式の連番。メールの件名と返信先アドレスに埋め込み、返信メールの紐付けに使う |
| メッセージ（Message） | 問い合わせに紐付く送受信の 1 通。フォーム送信、スタッフの返信、お客様の返信メールを含む |
| 内部メモ（Note） | お客様には見えない、スタッフ向けの記録 |
| イベント（Event） | ステータス変更や担当者変更などの操作履歴 |
| 担当者 | 問い合わせに割り当てられたスタッフ |
| 要返信 | お客様の最新メッセージにスタッフがまだ返信していない状態 |
